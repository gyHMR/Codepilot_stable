# Codepilot Web 安静工作台设计

## 1. 目标

将现有偏“科技控制台”风格的 Web 页面重构为简洁、高效、适合长期管理代码项目的三栏工作台。用户打开页面后的核心工作流是：选择或新建 Session，向 Agent 下达任务，观察必要的执行过程并处理审批，同时掌握项目、Git 和任务状态。

本次允许重写现有前端组件和样式，不要求兼容旧前端的视觉结构或组件 API。后端仍遵守项目既有依赖方向，Web Interface 通过稳定 DTO 适配内部模块，不能让 Core、Tools 或 Sessions 依赖前端模型。

## 2. 设计原则

- 中央对话区是首要工作面，左右侧栏只提供导航和决策所需信息。
- 使用中性浅色、细分隔线和克制的状态色，不使用网格、霓虹、渐变、光晕或全大写装饰文字。
- 默认展示结论、阶段、修改摘要和验证结果；原始工具参数、长日志和完整 diff 按需展开。
- 对话内容、工具活动、审批和 Run 结果使用不同的结构化条目，不能全部拼成 Markdown。
- 所有布局和控件支持键盘操作、焦点管理、减少动态效果和窄屏折叠。

## 3. 页面信息架构

页面采用固定左栏、弹性中央区、固定右栏：

- 左侧 Session 栏：248px。
- 中央对话区：最小 560px，自适应；正文最大宽度约 860px。
- 右侧项目栏：304px。
- 顶部栏：52px。
- 输入区：最小 96px，随输入内容增高。

窗口变窄时先将右栏变为抽屉，再将左栏变为抽屉。中央对话始终保持完整可用，不保留占空间的图标窄栏。

## 4. 左侧 Session 栏

顶部依次显示 Codepilot、当前项目名、“新建 Session”按钮和可展开的搜索入口。Session 列表按“今天、最近 7 天、更早”分组，只有列表区域滚动。

Session 条目以可读标题为主，标题来源依次为用户设置标题、第一条消息生成的短标题和“新建会话”。第二行显示最近更新时间；只有正在运行、等待审批或失败时才显示状态标识。当前条目使用浅色背景和细左边线表示选中。

条目悬停时显示更多菜单，支持重命名和删除。删除需要轻量二次确认。新建成功后立即进入空白对话区并聚焦输入框。列表不展示完整 Session ID、模型、权限模式或消息数量。

## 5. 中央对话区

### 5.1 顶部栏

显示可重命名的 Session 标题。右侧只保留 Run 状态、取消操作和更多菜单，不以 Session ID 作为主标题。

### 5.2 Timeline 条目

统一 Timeline 包含：

- `user_message`：用户消息，靠左显示。
- `assistant_message`：Agent Markdown 回复，靠右显示。
- `activity_group`：工具、文件和命令活动摘要。
- `approval_request`：需要用户决策的操作。
- `run_result`：修改文件和验证结果。
- `error`：可操作的错误与恢复提示。

消息正文保持稳定宽度，不使用聊天气泡堆叠。流式内容在同一个 Agent 条目内增长，不额外创建“直播”卡片。

### 5.3 Markdown

Agent 正文支持标题、段落、粗体、斜体、列表、引用、链接、表格、任务列表、行内代码和 fenced code。标题字号受工作台排版约束，超宽表格在条目内部滚动。

代码块显示语言和复制按钮；长代码块限制默认高度并可展开；diff 使用增加、删除和上下文语义色。Markdown HTML 不执行，链接和插件输出经过安全清理。

### 5.4 Agent 活动

默认展示当前阶段、工具操作摘要、修改文件摘要、测试统计及阻塞原因。完整工具参数、原始输出、异常栈、逐次文件读取和完整 diff 默认折叠。模型内部推理不展示。

工具活动按 Run 聚合，例如“读取 3 个文件、修改 2 个文件、执行 1 次测试”。文件条目可以展开 diff；测试条目优先展示通过数、失败数和耗时。

### 5.5 审批

审批插入触发它的 Timeline 位置，显示工具名、风险等级、操作摘要和影响范围。默认提供“允许一次”和“拒绝”，详细参数可展开。处理后收缩为一行历史结果。右侧只提示存在审批，决策始终在中央完成。

### 5.6 输入区

输入框固定在中央底部并自动增高。左侧命令按钮打开可搜索的命令 Popover；当前阶段不实现输入 `/` 自动触发。右侧根据状态显示发送或停止按钮。控件使用标准图标和 Tooltip，不长期展示快捷键说明。

## 6. 右侧项目栏

右栏按“项目、当前任务、本次运行、环境”排序，使用分隔线而不是嵌套卡片。

项目区显示项目名、工作区路径、Git 分支和修改文件数量。点击修改摘要展开文件列表，文件显示新增、修改或删除状态，并可打开中央 diff 详情。

任务区显示任务摘要、完成步数和步骤列表。当前步骤使用主强调色，完成步骤弱化，未开始步骤保持中性。步骤可展开详情和验证条件。没有结构化 Plan 时明确显示未创建计划，不生成虚假步骤。

本次运行只显示分析、工具执行、等待审批、生成回复、验证、完成或失败等关键阶段与运行时间。结束后收缩为一行结果。

环境区紧凑展示模型、权限模式和 SSE 连接状态。Context 使用量可以后续添加，但不展示内部层级与遥测细节。

## 7. 视觉系统

默认使用中性浅色主题：冷灰页面背景、白色工作区、深灰主文字和低对比度分隔线。蓝色表示主操作与运行，绿色表示完成，黄色表示等待审批，红色表示失败或危险。

普通正文使用适合中文的无衬线字体；代码、路径、命令和分支使用等宽字体。正文约 14px，区域标题 14–18px，辅助信息约 12px。间距遵循 4px/8px 体系，圆角限制在 4–8px。

所有图标使用 Lucide。交互动画控制在 120–180ms，并尊重 `prefers-reduced-motion`。加载和更新保持局部稳定，不引起整页跳动。

## 8. 前端技术方案

保留 React、Vite、React Router、React Query、React Markdown 和现有 SSE 客户端。新增：

- Radix Primitives：Popover、Dropdown Menu、Tooltip、Dialog、Collapsible 等无障碍交互。
- Lucide React：统一图标。
- remark-gfm：GFM 表格、任务列表和删除线。
- 按需代码高亮模块：只注册常见语言并延迟加载。

不引入 Ant Design、MUI、Redux 或 Zustand。样式采用全局 tokens、global/markdown 基础样式和组件级 CSS Modules，不再维护单个巨型 `app.css`。

前端按 `layouts`、`features/sessions`、`features/conversation`、`features/project`、`components/ui`、`api`、`events` 和 `styles` 分区。`WorkspacePage` 只负责页面级组合与 Query/SSE 接线，不承载所有业务渲染逻辑。

## 9. Web 数据协议

Web Interface 增加 mapper，将内部消息、Run、Tool、Approval、Plan 和 Workspace 状态转换为稳定 Web DTO。前端不直接依赖内部领域对象，也不解析 Markdown 推断工具状态。

历史 REST 数据与实时 SSE 数据最终都转换为带稳定 ID、Session ID、Run ID、时间和类型的 `TimelineItem`。SSE 对外事件收敛为：

- `assistant.started`、`assistant.delta`、`assistant.completed`
- `activity.updated`
- `approval.requested`、`approval.resolved`
- `run.status_changed`、`run.completed`
- `plan.updated`、`workspace.changed`
- `error`

事件保留 `event_id` 和递增序号。重连使用最后事件 ID 补发，前端按稳定 ID 去重。

REST 需要支持 Session 列表、创建、重命名、删除、详情、Timeline、提交消息、提交命令、取消、审批，以及 workspace summary/changes。Session DTO 增加标题、更新时间和简化状态；Workspace DTO 提供项目名、路径、Git 分支和修改文件摘要。

React Query 管理持久化服务端数据，SSE reducer 只管理实时增量、Run 状态和审批。Run 完成、Plan 更新和 workspace 变化时精确刷新关联 Query，Git 状态不高频轮询。

## 10. 错误与恢复

- API 错误统一转换为可读的行内错误，保留可重试操作。
- SSE 断线显示低干扰连接状态并自动重连，不清空已有 Timeline。
- 流式回复中断时保留已收到内容，并标记为未完成。
- Session、Timeline 或项目信息加载失败时分别降级，不让整个工作台黑屏。
- 未知事件类型记录到开发日志并忽略，不能导致 reducer 崩溃。
- 所有后端错误详情继续执行脱敏，前端不显示密钥、完整环境变量或不必要的绝对路径参数。

## 11. 测试范围

测试聚焦高价值行为：

- Session 新建、选择、重命名和删除。
- Timeline 类型映射、Markdown 安全渲染和流式增量合并。
- 工具摘要折叠、审批决策和 Run 取消。
- 右栏任务、Git 与连接状态。
- SSE 重连、重复事件和单区域加载失败。
- 桌面与窄屏关键布局不重叠。

保留 Vitest 与 Testing Library。后端补充 DTO mapper 和新增 API 的聚焦测试，不扩大到与 Web 无关的模块。

## 12. 迁移与范围

实施时直接建立新组件目录和视觉系统，再替换 `WorkspacePage`。旧组件和旧 CSS 在新页面验证完成后删除，不维持双实现或兼容适配层。

本次包含 Session 管理、结构化对话、Markdown、工具活动、审批、任务状态、Git 摘要和响应式三栏布局。不包含公网认证、多人协作、在线文件编辑器、完整 IDE、终端模拟器、可视化图表或多主题编辑器。
