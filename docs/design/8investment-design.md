# 投研助手垂域设计

## 文档状态

本文定义 Codepilot 从通用 Coding Agent 向垂直领域演进的第一份落地设计：**个人投资研究助手（Investment Research Assistant）**。本文只定义业务定位、领域模型、工作流、评测与合规边界，不改变既有架构依赖方向。

领域能力全部通过现有扩展点接入，Core 决策循环不作结构性修改：

- 领域工具 → `tools`（注册、编解码、权限、审批、执行、结果防护）
- 领域记忆 → `sessions/memory`（准入、召回、生命周期）
- 长文档上下文 → `sessions/context`（预算、投影、变薄、压缩）
- 溯源与审计 → `observability`（事件、Trace、脱敏、报告）
- 质量度量 → `evaluation`（证据、Scorer、报告）
- 长任务与恢复 → `sessions` + `runtime`（checkpoint、恢复、审批挂起）
- 领域工作流编排 → `extensions/skills` + `runtime/subagents`

一句话定位：

> 把分析师的「读财报 → 抠数据 → 校验 → 对标 → 写报告 → 跟踪观点」变成一条**可编排、可溯源、可恢复、可评测**的研究流水线。

## 1. 背景与定位

### 1.1 为什么选择投研

选择投研作为第一个垂域，基于三个判断：

1. **市场已验证**。开源生态中已有成熟项目验证需求，例如价值投资研究框架（AI Berkshire，16.7k stars）与本地优先投研工作台（Folio）。有竞争说明有真实应用前景，而不是伪需求。
2. **能力可度量**。投研是少有的「每个智能动作都有 ground truth」的领域：财报数字、勾稽关系、引用页码、计算过程全部可自动核验。评测闭环能做得又深又真，这是「不是玩具」的最硬证据。
3. **与企业 Agent 岗位对齐**。企业级 Agent 招聘普遍要求：任务规划、上下文管理、记忆、工具调用、工作流编排、安全审批、可观测性、评测体系。投研场景天然需要全部这些能力，且业务背景清晰。

### 1.2 产品定位与边界

定位：**面向个人投资者的研究助手**，帮助用户完成从信息收集、财务分析到研究结论沉淀的完整研究循环。

明确不做（边界即安全性）：

- 不做投资建议、荐股、评级输出
- 不做交易执行、下单、资金操作
- 不做实时高频行情与量化交易
- 不抓取来源不明或违反服务条款的数据

### 1.3 兼顾方向：机构投研工作流

个人投研与机构投研共享同一套领域模型与工具协议。本文以个人投研为落地形态，领域层不做「个人限定」假设，后续可通过扩大数据源与审批策略演化为机构投研工作流（覆盖报告、多角色审核、合规留痕）。

## 2. 业务场景与需求

### 2.1 目标用户

| 用户 | 核心诉求 |
|---|---|
| 个人投资者 | 快速理解一家公司，形成自己的可追踪的研究结论 |
| 求职者（金融方向） | 学习并复用专业研究流程与纪律 |
| 研究者 | 批量、结构化地整理公司财务事实与行业对比 |

### 2.2 核心工作流

**W1 个股深度研究（主打）**

```text
用户请求「研究 XX 公司」
  → 生成研究计划
  → 数据采集（行情 / 多年财务 / 公告，多工具并行）
  → 财务指标计算（精确计算工具，不用模型心算）
  → 多源交叉验证（≥2 个来源，误差超阈值告警）
  → 同业对标（2-4 家公司）
  → 估值计算（PE / PB / DCF）
  → 生成带引用的研究报告（每个数字标注来源）
  → 用户审批
  → 归档为投资论点
```

**W2 财报深读**

```text
用户上传或指定财报（10-K / 10-Q / 年报）
  → 长文档解析与结构化抽取（三大报表）
  → 勾稽校验（资产 = 负债 + 权益、现金流对账）
  → 关键指标计算与同比环比
  → 生成财报点评（带页码引用）
```

**W3 持仓与自选监控、异动归因**

```text
定时或事件触发
  → 扫描自选/持仓（价格异动、财报发布、新闻）
  → 发现异动 → 多智能体并行侦察（公司事件 / 监管政策 / 行业对手 / 市场情绪）
  → 归因判断（价值事件 / 情绪波动 / 真因不明）
  → 生成提醒并更新相关论点
```

**W4 投资论点追踪**

```text
记录投资论点（假设 / 证据 / 结论 / 置信度）
  → 新数据到来
  → 漂移检测（事实变化 / 估值变化 / 措辞变化）
  → 提示论点是否被证伪
  → 更新或归档
```

### 2.3 功能需求分层

| 层 | 功能 | 优先级 |
|---|---|---|
| L1 数据接入 | 行情、三大报表、财务指标、公告、宏观、持仓 | P0 |
| L2 查询检索 | 自然语言问数、文档检索、数据新鲜度管理 | P0 |
| L3 分析 | 指标计算、勾稽校验、多源交叉验证、同业对标、估值、组合分析、异动归因 | P0 |
| L4 生成 | 研究报告、财报点评、投资论点、带引用输出 | P0 |
| L5 监控提醒 | 价格预警、财报日历、持仓异动、论点漂移 | P1 |
| L6 长期记忆 | 用户偏好、覆盖档案、历史观点与决策记录 | P1 |
| L7 合规治理 | 免责声明、发布前审批、溯源审计、脱敏 | P1 |

需求设计原则：**数据新鲜度可见，缺失显示为空，绝不编造数字**；所有结论必须回答「你凭什么这么说」。

| 长期记忆 | `sessions/memory`（admission / recall / lifecycle） | 覆盖档案、投资论点、历史观点 |

## 4. 领域模型设计

### 4.1 领域记忆 Schema

领域记忆写入 `sessions/memory`，沿用既有准入（admission）与生命周期规则，新增四类领域条目：

```text
CompanyProfile     覆盖公司档案：代码、名称、行业、产业链位置、关注理由
FinancialFact      财务事实：指标名、数值、期间、来源引用（source_ref）、新鲜度
InvestmentThesis   投资论点：假设、证据链、结论、置信度、状态（成立/证伪/观察）
ResearchReport     研究报告：议题、章节、每条结论的 evidence_refs
```

关键约束：

1. `FinancialFact` 必须携带 `source_ref`（来源文件 + 位置），无来源不入库；
2. `InvestmentThesis` 的状态变更必须记录触发原因（新证据或漂移检测结果）；
3. 领域记忆与 Context 摘要严格分离，报告摘要不会自动升格为长期记忆。

### 4.2 领域工具清单

全部工具走现有 `tools` 链路（参数校验 → 权限解析 → 审批 → 执行 → 结果防护）：

| 工具 | 用途 | 副作用 | 权限级别 |
|---|---|---|---|
| `quote.read` | 读取行情 | 无 | read-only |
| `filing.fetch` | 下载财报/公告到工作区 | 写工作区文件 | workspace-write |
| `financials.extract` | 财报结构化抽取（三大报表） | 无（读工作区文件） | read-only |
| `metrics.compute` | 精确财务计算（Decimal） | 无 | read-only |
| `footing.check` | 勾稽校验（确定性规则） | 无 | read-only |
| `sources.cross_validate` | 多源交叉验证与偏差告警 | 无 | read-only |
| `peers.compare` | 同业对标 | 无 | read-only |
| `valuation.compute` | 估值计算（PE/PB/DCF） | 无 | read-only |
| `report.draft` | 生成带引用报告草稿 | 写工作区文件 | workspace-write |
| `report.publish` | 报告定稿归档 | 归档副作用 | 需审批 |
| `thesis.update` | 更新投资论点 | 改长期记忆 | 需审批 |
| `thesis.diff` | 论点漂移检测 | 无 | read-only |

设计原则：**计算类能力一律工具化**，模型只负责选择与解释，不承担数值运算；**有副作用的能力（发布、改记忆）必须审批**。

### 4.3 工作流编排示例（W1）

```text
Core 计划
  ├─ 并行批次 A：quote.read + filing.fetch + financials.extract
  ├─ 计算批次 B：metrics.compute + footing.check + sources.cross_validate
  ├─ 对标批次 C：peers.compare + valuation.compute
  ├─ 撰写批次 D：report.draft
  └─ 审批批次 E：report.publish + thesis.update（等待用户）
```

每个批次是一个 Core 边界（before_tools / after_tools），过程中的工具结果、Context 投影与决策事件全部进入 Run Trace，支持中断后从最近边界恢复。

## 5. 可观测与溯源

研究结论的可信度取决于证据链：

1. **证据链结构**：`结论 → 数据点 → 来源引用（文件 + 位置）→ 原始工具调用记录`，四层全部进入 `RunTrace`；
2. **报告标注**：生成报告时，每个关键数字附带来源标记，缺失来源的数字不允许进入定稿；
3. **审计能力**：任意一份历史报告可回放其生成过程（用了哪些工具、哪次投影、哪个模型调用）；
4. **脱敏**：持仓与账号信息在事件、Trace、报告落盘前统一经过脱敏链路。

## 6. 评测设计

投研场景的评测锚点（接入现有 `evaluation`）：

| 指标 | 定义 | Ground Truth 来源 |
|---|---|---|
| `research.extraction_accuracy` | 财报抽取字段准确率 | SEC XBRL 结构化数据逐字段比对 |
| `research.footing_consistency` | 勾稽关系一致率 | 确定性规则（资产=负债+权益等） |
| `research.citation_recall` | 引用准确率 | 数字位置 vs 财报页码 |
| `research.compute_accuracy` | 计算正确率 | 已知答案的数值题集 |
| `research.cross_validation_coverage` | 关键数据多源覆盖比例 | 来源记录 |
| `research.attribution_quality` | 异动归因质量 | 注入已知事件的模拟场景 |
| `research.thesis_drift_accuracy` | 漂移检测准确率 | 人工构造的论点变更样本 |

评测用例纳入离线 Benchmark：历史财报样本 + 注入事件场景 + 论点变更样本，产出可复现报告。

## 7. 合规与安全

1. **合规声明**：所有输出附带免责声明，明确定位为研究辅助，不构成投资建议；
2. **发布审批**：报告定稿、论点更新一律走审批，审批记录进入 Session；
3. **数据边界**：仅使用公开数据源与用户提供的数据，不绕过访问控制；
4. **信息脱敏**：持仓、账户等敏感信息在落盘与展示前统一脱敏；
5. **数据诚实**：数据不可用与负面证据严格区分，缺失数据不得推断填充。

## 8. 数据源

| 市场 | 数据源 | 用途 |
|---|---|---|
| A 股 | `akshare` / `tushare` | 行情、财务、公告 |
| 美股 | `yfinance` + SEC EDGAR | 行情、10-K/10-Q（含 XBRL 结构化数据） |
| 补充 | 用户导入文件 | 研报、调研纪要、自定义数据 |

数据源通过领域工具封装，对上层只暴露统一的数据契约；每个数据点携带 `source_ref` 与新鲜度标记。

## 9. 落地里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 领域地基 | 四类记忆 Schema + 数据与计算工具（quote / financials / metrics / cross_validate） | 工具链路单测全过，Fact 必须带来源 |
| M2 W1 端到端 | 个股深度研究完整工作流 + 报告溯源 | 选一只美股跑通全流程，报告数字全部可溯源 |
| M3 评测闭环 | XBRL ground truth + 抽取/勾稽/引用 Scorer | 产出可复现的评测报告 |
| M4 监控与归因 | W3 定时监控 + 多智能体异动归因 | 中断可恢复，注入事件归因正确 |
| M5 论点与合规 | W4 论点追踪 + 审批与免责收口 | 论点漂移可检出，发布全部经审批 |

## 10. 验收标准

1. 一次个股深度研究全程可回放：每个数字可定位到来源文件位置；
2. 任意中断（进程退出、审批挂起）后可从最近边界恢复，不重复执行副作用；
3. 评测可复现：抽取准确率、勾稽一致率、引用准确率在固定样本上结果稳定；
4. 有副作用的操作（发布、改记忆）全部经过审批并有审计记录；
5. 缺失数据诚实呈现，系统中不存在无来源的财务数字。
