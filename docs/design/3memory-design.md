# 记忆系统设计思路

## 设计目标

记忆系统解决的问题是：Agent 在多轮任务中应该记住长期有价值的项目知识、用户纠正和已验证经验，但不能把聊天历史、工具日志和当前任务进度全部混进长期记忆。

Codepilot 的记忆系统只保存跨任务可复用的信息。

```text
用户明确要求记住的约束
  + 用户纠正
  + 项目决策
  + 已验证修复经验
  -> 长期记忆
```

不进入记忆：

- 当前任务进度。
- 临时错误日志。
- 大段工具输出。
- 文件摘要。
- run trace。
- 未验证的猜测。

## 核心原则

### 记忆不是聊天历史

聊天历史是会话事实源，记忆是跨任务复用知识。两者不能混用。

如果把所有对话都塞进 memory，模型会越来越难区分长期规则和临时任务描述。

### 记忆必须可解释

每条记忆都应该能回答：

- 为什么写入。
- 来自用户、命令还是运行结果。
- 何时召回。
- 因为什么信号召回。
- 是否被删除或替代。

### 经验必须经过验证闭环

单次失败不应直接成为长期经验。更可靠的经验来自：

```text
失败
  -> 修复
  -> 验证通过
  -> 沉淀经验
```

这样可以避免把错误尝试写成“经验”。

## 记忆类型

当前设计保留少数几类记忆：

| 类型 | 含义 |
---|---
| correction | 用户纠正，例如“不是 X，而是 Y” |
| constraint | 长期约束，例如项目定位、偏好、禁止事项 |
| decision | 项目设计决策 |
| experience | 经过验证的修复经验 |

这些类型足够覆盖当前学习型 Coding Agent 的核心需求。不要轻易扩展成过多类别。

## 记忆作用域

记忆分为两个作用域：

| 作用域 | 含义 |
---|---
| project | 对整个项目长期有效 |
| session | 只在当前会话内有效，适合尚未确认可长期复用的经验 |

项目级记忆适合用户明确要求记住的规则、纠正和设计决策。会话级记忆适合刚从某次 run 中提炼出的经验，后续可以在重复出现后提升。

## 写入时机

记忆写入有三个入口。

### run 开始前：用户明确记忆意图

如果用户说“请记住”“以后都要”“纠正一下”，系统可以把这类长期规则写入项目级记忆。

普通任务请求不写入记忆。例如“帮我修复测试失败”只是当前任务，不是长期知识。

### 命令入口：用户手动管理

用户可以通过命令添加、查看、删除或提升记忆。手动入口的设计目标是让用户能纠正记忆系统，而不是完全依赖自动判断。

### run 结束后：提炼经验

当一次 run 形成可验证闭环时，系统可以提炼经验：

- 哪类失败出现了。
- 后续如何修复。
- 哪个验证证明修复有效。
- 哪些路径和错误信号可以作为召回触发器。

这类经验先进入会话级记忆，重复出现后再考虑提升为项目级经验。

## 召回机制

记忆召回发生在模型调用前，由上下文治理链路触发。召回不只看用户最后一句话，还要看当前任务状态。

召回信号包括：

- 最近用户请求。
- active files。
- 当前任务阶段。
- 当前动作意图。
- 最近错误类型。
- 当前上下文模式，例如问答、修复、验证。

召回结果按优先级组织：

1. 用户手写 pinned memory。
2. correction。
3. always constraint。
4. 与当前任务相关的 decision。
5. 与当前错误或动作相关的 experience。

召回结果要带原因。模型看到记忆内容，开发者能在报告里看到为什么召回。

## 冲突与删除

记忆需要支持演化。

设计规则：

- 同 key 的约束或经验应合并，不应无限追加重复记录。
- 新 correction 可以替代旧 constraint、decision 或 experience。
- 删除采用逻辑删除，保留审计痕迹。
- 被删除或被替代的记忆不再召回。

这样可以避免记忆库越用越脏，同时保留解释能力。

## 与其他模块的边界

| 模块 | 边界 |
---|---
| context | 负责召回并渲染记忆，不负责写入长期记忆 |
| sessions | 保存记忆文件和事件，控制生命周期 |
| task recovery | 保存当前任务进度，不属于长期记忆 |
| tools | 提供工具证据，但不直接决定写 memory |
| observability/evaluation | 读取记忆召回和写入证据，用于分析效果 |

记忆系统不应直接执行工具，也不应把工具日志原文复制进长期记忆。

## 设计取舍

当前设计不做：

- 向量数据库。
- LLM 自动总结所有历史。
- 置信度学习模型。
- 从单次失败直接沉淀长期经验。
- 自动写用户手动 pinned memory 文件。

目标是让每条记忆都能讲清楚：

```text
为什么写入
为什么召回
是否仍然有效
如何被用户删除或纠正
```
